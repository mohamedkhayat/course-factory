# course-factory

The vocabulary of course-factory: an app that turns study material into interactive courses generated by local models.

## Language

**Course**:
Everything generated from one body of study material: an ordered list of Chapters, plus the Exams and Labs that sit beside them.
_Avoid_: module, class, subject

**Goal**:
What a Course is for: Cram (an exam is coming, so content is ranked by Exam Weight and aimed at the exam date) or Deep (learn it properly, in the professor's order, with full proofs and extensions). Every Course has exactly one Goal, and it can be switched.
_Avoid_: mode, track, profile

**Exam Weight**:
How often a topic appears in a Course's Past papers.
_Avoid_: frequency, importance

**Priority**:
The owner's per-Chapter adjustment on top of the Goal: focus, normal, light, or skip.
_Avoid_: weight (that is Exam Weight)

**Chapter**:
An ordered part of a Course, made of an ordered list of Sections.
_Avoid_: unit, lesson, milestone

**Section**:
An ordered part of a Chapter, made of an ordered list of Blocks.
_Avoid_: page, lesson, topic

**Block**:
One use of a Component inside a Section: which Component, its content as data that fits that Component's shape, and citations to the source pages. A Block holds no code and never contains another Block.
_Avoid_: widget, card, element

**Concept**:
One teachable idea, command or fact, named once per Course in the outline and taught in exactly one Section. A practice Block lists the Concepts it tests, and may test only Concepts taught by its own Section or an earlier one.
_Avoid_: topic, skill, notion

**Chapter plan**:
The design of a Chapter made once before its Sections are written: per Section, its Objectives, the misconceptions its quizzes target, the practice ramp (worked, faded, independent, exam) and the one visual worth drawing. Plain code holds it to the rules in docs/research/learning-design.md; it is kept on the Chapter and reused when a Section is regenerated.
_Avoid_: outline (that is the Chapter and Section list), lesson plan

**Objective**:
What the learner can do after a Section, at one level (remember, understand, apply, analyse), tied to the Concepts it uses and the Question Types it prepares for. Every Objective is practised at its level.
_Avoid_: goal (that is the Course's Goal), outcome

**Component**:
A reusable piece of course UI, such as a theorem box or a quiz, that declares the shape of content it accepts. Components are code; Blocks are data.
_Avoid_: widget, template

**App View**:
A part of the app that every Course gets and that is not built from Blocks: the tutor panel, Exam mode, the Lab notebook, Copy grading, Review.
_Avoid_: page, screen, component

**Catalogue**:
The set of Components that content may use. Only Components in the Catalogue can appear in a Block.
_Avoid_: library, registry

**Prose Block**:
The escape hatch: a Block of free Markdown with math, used when no Component fits the content.
_Avoid_: raw block, HTML block

**Diagram kind**:
The shape a diagram takes, chosen from the relation it shows: tree (hierarchy), layers (dependency), nesting (containment), pipeline (process), cycle, state machine, fan-out (one-to-many). The model names the kind, each item's place in it and a short cited explanation per item; code lays it out and draws it. Clicking an item opens a card beside it with its explanation, its page and "Ask the tutor about this", highlighting it and its links while the rest dims; arrow keys walk the items, Escape closes, and in full screen the card docks at the side. Raw Mermaid stays only for faithful redraws of a slide.
_Avoid_: diagram template, layout

**Animation**:
Content that changes over time, in one of two renderers. A Stepped animation (the `stepped_animation` Component: a kind diagram plus cited, captioned steps that highlight, move a token, add, remove or relabel) runs in the page on the diagram engine: scrubbable, clickable, sharp at any zoom, used inside Sections. A Video is rendered by Manim from templates the model fills in, always narrated, used for maths and processes and for one overview per Chapter. Templates come in this order: Chapter overview, data and partition flow (records through partitions, narrow vs wide, shuffle, cache), equation transform, function and plot; then matrix and vector operations, and geometry. Videos are rendered in the background once their Section is checked; the Run never waits on them, and a failed render goes to the Review Queue. Videos are narrated by local text-to-speech, which also reads a Section's explaining Blocks aloud on Listen: generated the first time Listen is pressed, then kept until the Section changes.
_Avoid_: clip, movie

**Course chat**:
The tutor at Course level: a free-form conversation over every Chapter's material, whose answers mix Markdown with Blocks from the Catalogue (a diagram, a quiz, a worked example) drawn inline as part of the reply, the same renderers as in a Section and checked like any Block. A Block from an answer can be saved into a Section: the chat suggests the Section that teaches the Concepts it uses and the place after the Block it relates to most, the learner confirms or picks elsewhere, and the saved Block goes through the same checks as a generated one, Model-added and marked as from the chat, with Undo. Practice answered in the chat is recorded against the Concepts it tests (so weak Concepts show in Progress and come back sooner in Practice), but the Block itself stays in the conversation: it joins Practice only once saved into a Section, and it never counts toward a Section's progress. It is an App View of its own (Chat), with past conversations beside it and a wide column so Blocks get full width; the Section tutor can hand a conversation over to it. The Section tutor stays for questions on the open Section and for proposals that change it. Both show their work as it happens on one activity line (searching for a term, reading pages as links, writing a Block, checking or fixing it), collapsed to a summary once the answer is done; a Block in an answer shows as a placeholder of its kind until checked, never as raw JSON.
_Avoid_: assistant, big tutor

**Learner memory**:
One-line facts about how the owner learns, each with where it came from: a preference they stated ("no write-on-paper exercises"), or a pattern code finds in their results (three misses on narrow vs wide), Explain differently choices, skips and ratings. Saved automatically, shown as "Remembered: …" with Undo where it was made, and listed in Settings to edit or delete. Preferences hold across Courses; patterns in results belong to their Course. The tutor, the Course chat and the writing of Sections read it.
_Avoid_: profile, personalisation

**Listen**:
Hearing a Section read aloud by the Voice, following along: the sentence being read is highlighted and kept in view, a click on a sentence jumps there, and a bar holds play, ±10 s, speed and the Voice. It reads the explaining Blocks; code is announced, not read, and practice Blocks are skipped so no answer is heard. Maths is spoken as a person says it, in the Course language ("x au carré plus un"), converted by code from the LaTeX, never read as symbols: what reaches the Voice holds no backslash, dollar, underscore, caret or brace. It stops at the end of the Section and offers the next one, and keeps playing with the screen locked.
_Avoid_: read aloud, audio mode

**Dictation**:
Speaking instead of typing in Explain back, the tutor and the Course chat: a local Whisper model on the CPU transcribes in the Course language or English, the learner sees and can fix the transcript before it is sent, a tablet records while the host transcribes, and the audio is deleted once transcribed.
_Avoid_: voice input, STT

**Challenge**:
How the tutor and the Course chat treat what the learner says they understood: checked against the material, never praised when wrong or partial. What is wrong or missing is named plainly, then one follow-up question tests it from another side (why, what if, a counter-example, the exam's wording); a right answer earns a harder question, not praise alone. Misunderstandings found this way become Learner memory. Only in Test me, or when the learner answers the tutor's last question; a question the learner skips is dropped.
_Avoid_: quiz mode, Socratic mode

**Reply mode**:
How much the tutor and the Course chat do in one answer: Step (a Step answer), Explain (a full answer within the course), Test me (a Challenge), or Beyond the course (wider theory, marked as not from the course). Picked by the learner, else Step for a quoted line of a theoretical Course, else Explain.
_Avoid_: style (that is "Explain this differently")

**Course-first**:
How a theoretical Course is written and tutored: the course's own pages are the backbone, in their order and notation; its definitions, derivations, TD exercises and past Questions come before anything the model makes, and nothing is added that neither the pages nor the past Questions contain. A theoretical Section under half from_source (opening and recap aside) is flagged on Review with its course share.
_Avoid_: grounded mode, source mode

**Anchor**:
The course page a question is about: the page a quoted line comes from (found by its words), or the cited page of the Block a line was selected in.
_Avoid_: context page

**Step answer**:
The tutor's answer to "how does this line follow?": only the missing step, in the course's notation, from the Anchor and the pages before it and the Concepts taught so far; about 120 words and one chain of equations, no new theorem, no question back. Longer is shown and counted as a Failure class.
_Avoid_: short answer, hint

**Derivation**:
A Component holding the course's own derivation (a proof, a computation, a TD correction) line by line, each line verbatim from the pages; from_source and cited. Its Card hides one line: "what comes next?".
_Avoid_: proof Block, worked example (that is the model's own)

**Gap note**:
On a Derivation line where the course skips a step, at most two sentences on how it follows, written by the model, marked added and closed until tapped; never judged as the course's text.
_Avoid_: annotation, comment

**Drill**:
"Quiz me" in the Course chat: one question at a time (a quiz, gaps or Explain back) on the chosen Chapters, leaning on weak Concepts and the exam's Question Types, each answer met with a Challenge, a missed point coming back soon after; it stops at the time asked or when the learner says so, and ends with what was right, what to review (as links to Sections) and what was remembered.
_Avoid_: quiz session, test

**Course language**:
The language a Course is written in for its learner, chosen at the found gate: English, French, or mixed (the source's wording in its own language, the model's own explanations in English). Everything the model makes follows it: Blocks, diagram labels and explanations, Video text and narration, and what Listen reads. Quotes and the exact names of commands, functions and files stay as in the material, and Listen and narration read each passage with a Voice for its language. Conversations are the exception: the tutor and the Course chat answer in the language the learner writes in, keeping the material's terms, quotes and exam wording as they are; a Block they write still follows the Course language, since it may be saved into a Section.
_Avoid_: locale, translation

**Voice**:
The local text-to-speech model that reads Listen and narrates Videos, picked in Settings and switchable at any time: Kokoro by default (CPU), or Audio8, Klein or OmniVoice. Each Voice runs in its own isolated environment, pinned to an exact revision, and reads in the Course language. Audio is kept per Section and Voice, so switching back costs nothing and a new Voice is generated on the next Listen.
_Avoid_: TTS engine, speaker

**Source**:
One file of study material imported into a Course, such as a PDF, a notebook, or a data file. Sources are copies; the original folder is never touched. They come from a folder the owner picks, or from an MIT OpenCourseWare course found by search, whose notes, problem sets and exams are downloaded into a folder with one sub-folder per OCW kind.
_Avoid_: document, upload, file

**Role**:
What a Source is for in its Course: course notes, exercise sheet, lab, past exam, correction, personal notes, or data.
_Avoid_: type, category

**Pairing**:
The link between a Source and the Source holding its correction, such as a TD and its corrigé.
_Avoid_: match, link

**Passage**:
A searchable piece of one page's transcription. Every Passage belongs to exactly one page, so a search hit is already a Citation.
_Avoid_: chunk, snippet, document

**Citation**:
A pointer from a Block to an exact place in the source material: a file, a page, and optionally a short quote.
_Avoid_: reference, source link

**Origin**:
Whether a Block is From source (taken from the material, and must carry at least one Citation) or Model-added (written by the model, Citations optional, always marked as such).
_Avoid_: provenance (reserved for who made a Component)

**Exam**:
A timed paper at Course level: a title, a duration, the Chapters it covers, and an ordered list of Questions. It is either a Past paper or a Mock exam.
_Avoid_: test, quiz

**Past paper**:
An Exam rebuilt faithfully from a real exam in the material, with its correction taken from the corrigé.
_Avoid_: annale, old exam

**Cohort**:
The year of study a Past paper was set for, read from its header ("Classe(s) : 4DS" is year 4). Only the Past papers of the learner's Cohort weigh the Course; the others stay as practice.
_Avoid_: level, class, promotion

**Mock exam**:
A new Exam the model writes in the style of the Past papers, covering the same recurring question types.
_Avoid_: practice test, sample exam

**Question**:
One item of an Exam: a statement, its points, a model answer, and optionally a Marking scheme.
_Avoid_: exercise (an exercise lives in a Section)

**Marking scheme**:
Which steps of a Question's answer earn which points, so a copy can be graded step by step.
_Avoid_: rubric, barème

**Lab**:
A guided coding notebook at Course level, usually from a TP: an intro, data files, and an ordered list of Steps. It lists the Chapters it covers.
_Avoid_: TP, notebook, Application Lab

**Step**:
One task in a Lab: a statement, starter code, a Check, Hints, and a Solution that stays locked until the Check passes or the owner gives up.
_Avoid_: cell, exercise, question

**Check**:
Hidden code that tests the owner's work on a Step, for example by comparing it against a reference at sample points. Plots are not Checked.
_Avoid_: test, grader

**Hint**:
A nudge on a Step, revealed one at a time, that stops short of the Solution.
_Avoid_: tip, clue

**Lab Environment**:
The pinned, offline software setup that a Course's Labs run in. It is fixed when the Course is generated, so a Lab behaves the same months later.
_Avoid_: image, container, runtime

**Generation Run**:
One pass of turning material into a Course, which pauses at Approval Gates and can resume after a stop.
_Avoid_: job, build, pipeline run

**Approval Gate**:
A point in a Generation Run where it waits for the owner to approve, edit or reject what was produced.
_Avoid_: checkpoint, review step

**Harness**:
Everything that shapes the local model's work apart from its weights: prompts, skills, tool guidance and checks. It is versioned as a whole.
_Avoid_: prompts, config

**Model step**:
One call to the local model for one job, such as reading a page or proposing Roles. Every Model step writes a Trace.
_Avoid_: step (that is a Lab Step), call, job

**Trace**:
The record of one model step: the Harness version, inputs, output, check results, and what the owner did with it.
_Avoid_: log, event

**Review Queue**:
The model-made Components, and the flagged Blocks auto-resolve could not fix, waiting for Claude Code to promote, fix or reject them. Claude Code works the queue from outside the app; the app itself never calls Claude.
_Avoid_: backlog, inbox

**Live work**:
Model work the owner is waiting on right now, such as a tutor reply or grading a copy. It takes priority over a Generation Run for the GPU.
_Avoid_: interactive job, foreground task

**Card**:
One spaced-repetition item made from a Block or a Question: a recall prompt or an auto-graded question. It unlocks once its Section has been read.
_Avoid_: flashcard, note

**Review**:
Going through the Cards due today. When an exam date is set, every Card comes due at least once before it.
_Avoid_: revision, study (too broad)

**Copy**:
The owner's handwritten work on a Question or an exercise, as ink, photos or a PDF, handed in for grading.
_Avoid_: submission, answer sheet

**Written answer**:
The owner's answer to an exercise Block, typed or uploaded, kept per Block and graded against the exercise's steps. Its uploads are a Copy.
_Avoid_: submission, response

**Paired Device**:
A device on the home network, such as a tablet, that the owner has allowed to use the app with a one-time code. The host machine itself needs no pairing.
_Avoid_: client, remote

**Focus Session**:
A timed work block, 25 minutes by default, that counts only active time and only if something was done in it.
_Avoid_: pomodoro, study session

**Daily Goal**:
How many Focus Sessions the owner aims to complete in a day.
_Avoid_: target, quota

**Streak**:
The run of consecutive days the Daily Goal was met. One missed day per week is forgiven.
_Avoid_: combo, chain

**Question Type**:
A recurring shape of exam question across past papers, answered with the same method, such as "prove a set is convex". Each has a trigger (how to recognise it) and an answer template.
_Avoid_: question category, pattern

**Exam Likelihood**:
How likely an item is to be needed in the exam (high, medium or low), from the points of the Question Types that use it.
_Avoid_: importance, priority (that is a Chapter setting)

**Cram Profile**:
A Chapter's cramming method: problem (worked problems, timed exercises), recall (definitions and theorems) or hands-on (commands and code).
_Avoid_: mode, style

**Cheat Sheet**:
The compiled summary of a Course or Chapter for the last days: definitions, formulas, methods, traps and commands from checked Blocks only, most likely first, about two printed pages.
_Avoid_: summary, crib sheet

**Cram Plan**:
The day-by-day schedule up to the exam date: learn, spaced retrieval passes, mixed practice, Mock exams, and a light last day.
_Avoid_: schedule, timetable

**Failure class**:
A recurring kind of generation problem, derived from a check message, flag or owner fix. The ledger in the Harness records how each is handled.
_Avoid_: error type, bug

**Heal**:
A deterministic fix code applies to model output before checking it.
_Avoid_: patch, cleanup

**Lesson**:
A short Harness rule for a Failure class code can't handle, added only to the Model steps it affects.
_Avoid_: tip, prompt tweak

**Refresh**:
Redoing only what changed after files in the Course folder changed: changed pages are re-read and only the Sections citing them are rewritten.
_Avoid_: re-ingest, rebuild

## Relationships

- An **Approval** or rejection recorded on a **Trace** is both a signal and an eval case for improving the **Harness**.
