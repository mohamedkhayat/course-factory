# course-factory

The vocabulary of course-factory: an app that turns study material into interactive courses generated by local models.

## Language

**Course**:
Everything generated from one body of study material: an ordered list of Chapters, plus the Exams and Labs that sit beside them.
_Avoid_: module, class, subject

**Goal**:
What a Course is for: Cram (an exam is coming, so content is ranked by Exam Weight and aimed at the exam date) or Deep (learn it properly, in the professor's order, with full proofs and extensions). Every Course has exactly one Goal, and it can be switched.
_Avoid_: mode, track, profile

**Exam Weight**:
How often a topic appears in a Course's Past papers.
_Avoid_: frequency, importance

**Priority**:
The owner's per-Chapter adjustment on top of the Goal: focus, normal, light, or skip.
_Avoid_: weight (that is Exam Weight)

**Chapter**:
An ordered part of a Course, made of an ordered list of Sections.
_Avoid_: unit, lesson, milestone

**Section**:
An ordered part of a Chapter, made of an ordered list of Blocks.
_Avoid_: page, lesson, topic

**Block**:
One use of a Component inside a Section: which Component, its content as data that fits that Component's shape, and citations to the source pages. A Block holds no code and never contains another Block.
_Avoid_: widget, card, element

**Component**:
A reusable piece of course UI, such as a theorem box or a quiz, that declares the shape of content it accepts. Components are code; Blocks are data.
_Avoid_: widget, template

**App View**:
A part of the app that every Course gets and that is not built from Blocks: the tutor panel, Exam mode, the Lab notebook, Copy grading, Review.
_Avoid_: page, screen, component

**Catalogue**:
The set of Components that content may use. Only Components in the Catalogue can appear in a Block.
_Avoid_: library, registry

**Prose Block**:
The escape hatch: a Block of free Markdown with math, used when no Component fits the content.
_Avoid_: raw block, HTML block

**Source**:
One file of study material imported into a Course, such as a PDF, a notebook, or a data file. Sources are copies; the original folder is never touched.
_Avoid_: document, upload, file

**Role**:
What a Source is for in its Course: course notes, exercise sheet, lab, past exam, correction, personal notes, or data.
_Avoid_: type, category

**Pairing**:
The link between a Source and the Source holding its correction, such as a TD and its corrigé.
_Avoid_: match, link

**Passage**:
A searchable piece of one page's transcription. Every Passage belongs to exactly one page, so a search hit is already a Citation.
_Avoid_: chunk, snippet, document

**Citation**:
A pointer from a Block to an exact place in the source material: a file, a page, and optionally a short quote.
_Avoid_: reference, source link

**Origin**:
Whether a Block is From source (taken from the material, and must carry at least one Citation) or Model-added (written by the model, Citations optional, always marked as such).
_Avoid_: provenance (reserved for who made a Component)

**Exam**:
A timed paper at Course level: a title, a duration, the Chapters it covers, and an ordered list of Questions. It is either a Past paper or a Mock exam.
_Avoid_: test, quiz

**Past paper**:
An Exam rebuilt faithfully from a real exam in the material, with its correction taken from the corrigé.
_Avoid_: annale, old exam

**Mock exam**:
A new Exam the model writes in the style of the Past papers, covering the same recurring question types.
_Avoid_: practice test, sample exam

**Question**:
One item of an Exam: a statement, its points, a model answer, and optionally a Marking scheme.
_Avoid_: exercise (an exercise lives in a Section)

**Marking scheme**:
Which steps of a Question's answer earn which points, so a copy can be graded step by step.
_Avoid_: rubric, barème

**Lab**:
A guided coding notebook at Course level, usually from a TP: an intro, data files, and an ordered list of Steps. It lists the Chapters it covers.
_Avoid_: TP, notebook, Application Lab

**Step**:
One task in a Lab: a statement, starter code, a Check, Hints, and a Solution that stays locked until the Check passes or the owner gives up.
_Avoid_: cell, exercise, question

**Check**:
Hidden code that tests the owner's work on a Step, for example by comparing it against a reference at sample points. Plots are not Checked.
_Avoid_: test, grader

**Hint**:
A nudge on a Step, revealed one at a time, that stops short of the Solution.
_Avoid_: tip, clue

**Lab Environment**:
The pinned, offline software setup that a Course's Labs run in. It is fixed when the Course is generated, so a Lab behaves the same months later.
_Avoid_: image, container, runtime

**Generation Run**:
One pass of turning material into a Course, which pauses at Approval Gates and can resume after a stop.
_Avoid_: job, build, pipeline run

**Approval Gate**:
A point in a Generation Run where it waits for the owner to approve, edit or reject what was produced.
_Avoid_: checkpoint, review step

**Harness**:
Everything that shapes the local model's work apart from its weights: prompts, skills, tool guidance and checks. It is versioned as a whole.
_Avoid_: prompts, config

**Model step**:
One call to the local model for one job, such as reading a page or proposing Roles. Every Model step writes a Trace.
_Avoid_: step (that is a Lab Step), call, job

**Trace**:
The record of one model step: the Harness version, inputs, output, check results, and what the owner did with it.
_Avoid_: log, event

**Review Queue**:
The model-made Components, and the flagged Blocks auto-resolve could not fix, waiting for Claude Code to promote, fix or reject them. Claude Code works the queue from outside the app; the app itself never calls Claude.
_Avoid_: backlog, inbox

**Live work**:
Model work the owner is waiting on right now, such as a tutor reply or grading a copy. It takes priority over a Generation Run for the GPU.
_Avoid_: interactive job, foreground task

**Card**:
One spaced-repetition item made from a Block or a Question: a recall prompt or an auto-graded question. It unlocks once its Section has been read.
_Avoid_: flashcard, note

**Review**:
Going through the Cards due today. When an exam date is set, every Card comes due at least once before it.
_Avoid_: revision, study (too broad)

**Copy**:
The owner's handwritten work on a Question or an exercise, as ink, photos or a PDF, handed in for grading.
_Avoid_: submission, answer sheet

**Paired Device**:
A device on the home network, such as a tablet, that the owner has allowed to use the app with a one-time code. The host machine itself needs no pairing.
_Avoid_: client, remote

**Focus Session**:
A timed work block, 25 minutes by default, that counts only active time and only if something was done in it.
_Avoid_: pomodoro, study session

**Daily Goal**:
How many Focus Sessions the owner aims to complete in a day.
_Avoid_: target, quota

**Streak**:
The run of consecutive days the Daily Goal was met. One missed day per week is forgiven.
_Avoid_: combo, chain

**Question Type**:
A recurring shape of exam question across past papers, answered with the same method, such as "prove a set is convex". Each has a trigger (how to recognise it) and an answer template.
_Avoid_: question category, pattern

**Exam Likelihood**:
How likely an item is to be needed in the exam (high, medium or low), from the points of the Question Types that use it.
_Avoid_: importance, priority (that is a Chapter setting)

**Cram Profile**:
A Chapter's cramming method: problem (worked problems, timed exercises), recall (definitions and theorems) or hands-on (commands and code).
_Avoid_: mode, style

**Cheat Sheet**:
The compiled summary of a Course or Chapter for the last days: definitions, formulas, methods, traps and commands from checked Blocks only, most likely first, about two printed pages.
_Avoid_: summary, crib sheet

**Cram Plan**:
The day-by-day schedule up to the exam date: learn, spaced retrieval passes, mixed practice, Mock exams, and a light last day.
_Avoid_: schedule, timetable

**Failure class**:
A recurring kind of generation problem, derived from a check message, flag or owner fix. The ledger in the Harness records how each is handled.
_Avoid_: error type, bug

**Heal**:
A deterministic fix code applies to model output before checking it.
_Avoid_: patch, cleanup

**Lesson**:
A short Harness rule for a Failure class code can't handle, added only to the Model steps it affects.
_Avoid_: tip, prompt tweak

**Refresh**:
Redoing only what changed after files in the Course folder changed: changed pages are re-read and only the Sections citing them are rewritten.
_Avoid_: re-ingest, rebuild

## Relationships

- An **Approval** or rejection recorded on a **Trace** is both a signal and an eval case for improving the **Harness**.
